# 개발 확인 도구

## device-preview.html — 기기별 레이아웃 확인

아이폰·아이패드·PC 화면 크기에서 페이지가 어떻게 보이는지 한 번에 한 기기씩 실제 CSS 픽셀로 확인한다.
`DESIGN_GUIDE.md` §26(화면 크기별 검증)의 4구간을 눈과 수치로 함께 확인하는 용도.

### 실행 방법

`file://` 로 열면 iframe 접근이 차단되어 측정이 안 된다. **반드시 로컬 HTTP 서버로 연다.**

저장소 루트에서:

```bash
# 파이썬이 있으면
python -m http.server 8899

# 또는 node 로 (파이썬이 스토어 스텁이면 이쪽)
npx --yes serve -l 8899 .
```

브라우저에서 `http://127.0.0.1:8899/tools/device-preview.html` 를 연다.

### 기능

- **기기 탭**: 아이폰 15 세로/가로, 아이패드 6세대 세로/가로, 아이패드 Air M3 11형 세로/가로, PC 웹
- **페이지 선택**: 전선 4개 페이지들, 6·25(단일 레인), 첫 화면
- **자동 판정**: `#timeline-scroll` 의 `scrollWidth - clientWidth` 를 측정해
  `가로 스크롤 없음`(초록) / `가로 스크롤 NNpx`(빨강) 로 표시
- **스크롤바 항상 표시**: 타임라인 컨테이너는 높이가 수만 px 이라 브라우저 기본 가로 스크롤바가
  문서 맨 아래(예: y=35,000px)에 붙어 화면 밖으로 나간다. 실제 아이폰에서는 화면 안에 보이므로,
  이 옵션이 뷰포트 하단에 고정된 대체 스크롤바를 그려 **실제 기기와 같게** 보이도록 한다.
  드래그해서 좌우로 밀 수도 있다.
- **화면 끝 표시**: 기기 화면 오른쪽 경계에 빨간 선을 그어 무엇이 잘리는지 본다.
- **확대율**: 화면이 모니터보다 크면 85~55% 로 줄여서 본다. 측정값은 축소와 무관하다.

### 주의

- 가로 스크롤이 **있어야 정상인 경우**도 있다. 아이폰 세로에서 전선 4개 페이지가 그렇다
  (4개를 393px 에 접으면 읽을 수 없어 의도적으로 스크롤을 남긴다).
  판정 배지의 빨강이 항상 버그를 뜻하지 않는다. `DESIGN_GUIDE.md` §26.4 를 함께 본다.
- CSS 를 고쳤는데 변화가 없으면 각 HTML 의 `?v=` 캐시 버전을 올렸는지 확인한다.
